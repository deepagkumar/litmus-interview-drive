Question 1

The high-value transaction that skipped validation

A payments team has this base class in a shared NuGet package:

public class TransactionProcessor
{
    public void Process(decimal amount)
    {
        Validate(amount);
        Console.WriteLine($"Processed {amount}");
    }

    protected void Validate(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Invalid amount");
    }
}

A new team writes:

public class HighValueProcessor : TransactionProcessor
{
    protected void Validate(decimal amount)   // compiler warning ignored
    {
        if (amount <= 0) throw new ArgumentException("Invalid amount");
        if (amount > 1_000_000) throw new ArgumentException("Needs approval");
    }
}

QA files a bug: a $5,000,000 transaction went through HighValueProcessor.Process() with no approval error. The developer insists their validation code is correct — and it is, in isolation.

Ask: Why didn't the new rule fire? What is the minimum change to the base class and the derived class to fix it?
